# CSRF Mitigation Report

## Vulnerability

Cross-Site Request Forgery (CSRF) occurs when an attacker causes an authenticated user's browser to perform an unwanted state-changing action.

## Root Cause

The application does not adequately verify that a state-changing request was intentionally generated by the authenticated user.

## Mitigation

Use a unique, unpredictable CSRF token for state-changing requests.

### Secure PHP

```php
session_start();

if ($_SERVER['REQUEST_METHOD'] === 'POST') {

    if (!isset($_POST['csrf_token']) ||
        !hash_equals($_SESSION['csrf_token'], $_POST['csrf_token'])) {
        die('Invalid CSRF token');
    }

    // Process the request
}
```

The token should be included in the legitimate form:

```php
<input type="hidden"
       name="csrf_token"
       value="<?php echo htmlspecialchars($_SESSION['csrf_token']); ?>">
```

## Additional Protections

* Generate unpredictable CSRF tokens.
* Validate tokens on every state-changing request.
* Use POST for state-changing operations.
* Configure cookies with appropriate `SameSite` attributes.
* Validate the `Origin` header where appropriate.
* Require re-authentication for highly sensitive operations.

## Result

The application verifies that state-changing requests contain a valid CSRF token before processing them.

## Conclusion

CSRF tokens provide the primary defense against unauthorized cross-site requests. Secure cookie configuration and origin validation can provide additional protection.
